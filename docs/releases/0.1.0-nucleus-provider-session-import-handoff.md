# Nucleus External Thread Import Handoff

Status: bounded non-published `0.1.0` handoff
Consumer authority: Nucleus

This handoff lets Nucleus browse and explicitly import harness-origin sessions
through the three complete Swallowtail routes. It changes no Nucleus source,
creates no synchronization service, and authorizes no consumer policy.

## Supported Route Boundary

The complete browse-select-import-replay-continue profile exists on:

| Route | Catalogue scope | Import revalidation | History and continuation |
| --- | --- | --- | --- |
| `codex.app-server` | working-resource cwd | exact thread read | `load_session` / `resume_session` |
| `kimi-code.acp` | working resource plus prepared state root | repeated exact list | `load_session` / `resume_session` |
| `opencode.http` | attached endpoint plus directory | health, lookup, and status | `load_session` / `resume_session` |

Support is route-specific. Codex exec, Kimi headless, and the OpenCode family
name do not inherit these claims. The
[provider route matrix](../guides/provider-route-matrix.md) classifies every
other harness route as discovery-only, attachment-only, blocked, or not
applicable and records its promotion gate.

## Consumer Flow

1. Nucleus selects one configured integration, working resource, model route,
   access policy, and qualified installed version.
2. It prepares that adapter's session catalogue and calls `list_sessions`.
3. It follows only opaque cursors issued by that prepared catalogue and keeps
   results inside the declared traversal bounds.
4. It presents candidates as observations. A candidate is not attachment
   authority and its provider reference is not a resume token.
5. The user explicitly selects one candidate whose import availability is
   `Available`.
6. Nucleus prepares the matching import operation. Swallowtail revalidates the
   exact candidate against current provider state and issues a
   `SessionResumeBinding` only on success.
7. Nucleus passes that binding to the matching prepared session's
   `load_session`. It persists the returned replay as a local projection.
8. Only after replay persistence succeeds does it expose the ready session for
   future turns. A later attachment without replay uses `resume_session`.

There is no background refresh, automatic import, raw-id attachment, route
fallback, or cross-resource scan.

## Nucleus-Owned Mapping

Keep one record per imported local thread:

| Field | Purpose |
| --- | --- |
| local thread id | Nucleus identity and persistence key |
| configured integration id | selects the same prepared adapter instance |
| working-resource identity | prevents cross-project attachment |
| model route and access selection | rebuilds matching preparation inputs |
| opaque persisted resume-binding bytes | durable authority input for exact restore |
| live `SessionResumeBinding` | sole in-process authority for load or resume |
| local replay import id | scopes one atomic replay projection |
| local replay/live boundary | records when ordinary future events begin |

Nucleus may persist non-authoritative route, resource, model, title, and source
labels for display. Export the live binding with
`SessionResumeBinding::export_persisted(prepared_session.plan())`; persist the
opaque bytes atomically with the local mapping. It must not persist a copied
provider session id and later construct a binding from it.

After restart, re-prepare the exact configured integration and parse the bytes
with `PersistedSessionResumeBinding::from_bytes`. Restore the live binding with
`SessionResumeBinding::restore_persisted`, supplying the new exact plan,
working resource, and access policy. Corruption, unsupported record versions,
or any attachment drift leaves the local thread readable but not resumable.
Offer explicit re-import. Never create a replacement provider session as an
implicit recovery path.

Provider-session management bindings are separate. An imported resume binding
does not authorize archive, restore, or delete. The existing
[lifecycle handoff](0.1.0-nucleus-provider-session-lifecycle-handoff.md)
governs those optional operations.

## Replay And Duplicate Boundary

`load_session` returns a bounded ordered `SessionReplayItem` collection and a
ready session handle. Every replay item carries the imported provider-session
reference, a replay sequence, a kind, and optional portable content. Nucleus
must persist the full replay projection before admitting future events from
that handle.

This establishes one unambiguous boundary:

- replay sequences belong to that completed load
- future runtime events receive Nucleus-owned local identities after replay
- one load does not interleave replay items with future events

The replay sequence is not a portable cross-import message identity. Providers
do not all expose stable message ids, and a repeated import may replay the same
history again. Therefore:

- reject a second import while the same durable binding is already mapped
  to a local thread
- never merge two imports automatically
- after a failed persisted-binding restore, require explicit user import and a
  consumer-selected create, replace, or merge policy
- do not infer duplicates by content equality inside Swallowtail

Nucleus may implement stronger provider-specific deduplication later, but that
is consumer policy and must not become a portable Swallowtail guarantee.

## Failure And UX Truth

| Evidence | Required consumer posture |
| --- | --- |
| route lacks the complete profile | do not show it as import-capable |
| `Unavailable(Active)` | disable import; do not steal or cancel the provider writer |
| `Unavailable(Archived)` | disable import; provider restore is a separate optional action |
| `Unavailable(IncompleteHistory)` | disable import; do not present partial history as resumable |
| `Unavailable(IncompatibleInterface)` | show unsupported installed interface; do not guess |
| resource mismatch or provider unavailable | disable the candidate and refresh explicitly |
| import drift or stale candidate | discard the candidate authority, refresh the catalogue, and require reselection |
| access or credential failure | ask for reauthorization of the selected route; do not fall back |
| unverified newer version | keep visible as unverified; attempt only under explicit consumer policy |
| load or replay failure | retain no resumable local mapping from that failed attempt |
| cleanup uncertainty | surface the safe diagnostic and do not fabricate readiness |

Discovery-only and attachment-only routes are not nearly supported routes.
Never expose a raw provider-id field as their substitute.

- Codex exact prepared-flow cases in
  [`provider_session_import.rs`](../../crates/swallowtail-adapter-codex/tests/prepared_profile_cases/provider_session_import.rs)
- Kimi pagination and import cases in
  [`provider_session_acceptance.rs`](../../crates/swallowtail-adapter-kimi/tests/provider_session_acceptance.rs)
  and [`provider_session_import.rs`](../../crates/swallowtail-adapter-kimi/tests/provider_session_import.rs)
- OpenCode prepared facade cases in
  [`session_import.rs`](../../crates/swallowtail-adapter-opencode/tests/prepared_facade/session_import.rs)
  plus its `session-import*.json` fixtures

Minimum Nucleus scenarios:

1. browse two pages, select once, import, persist ordered replay, then accept
   one future event
2. repeat selection while an in-process mapping exists and reject the duplicate
3. stale candidate fails before binding and forces refresh
4. active, archived, incomplete, incompatible, and wrong-resource candidates
   never appear resumable
5. access failure offers reauthorization only for the chosen route
6. restart restores the exact binding, resumes the same provider session, and
   never creates a fallback session; drift keeps the local projection readable
   but non-resumable
7. unsupported routes expose no raw-id escape hatch
8. import or load cancellation/deadline leaves no partial resumable mapping

These fixtures prove Swallowtail behavior. Nucleus remains responsible for its
database, transactional persistence, product copy, and UI tests.

## Rollback

External import is additive. Rollback hides the browse/import entry point and
keeps every already persisted local thread readable. It does not delete local
history, mutate provider state, or switch transports.

No registry publication, provider prompt, consumer edit, or management-binding
persistence promotion is part of this handoff.
