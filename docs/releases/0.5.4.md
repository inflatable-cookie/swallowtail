## Correction

The Contract 063 kernel remains the sole owner of caller, per-call, and optional
lease deadlines. The shared operation-listener now separates transport states.
Until a connection authenticates, the first byte of each frame must start inside
the 5-second accept window. Once a frame starts, the whole frame has a
10-second progress budget and each read waits at most 5 seconds. Once a
connection authenticates, no transport timeout applies while it is idle: the
idle wait ends on the next frame, peer end-of-stream, route revocation, or
listener close. Revoking a registration wakes its idle readers at once. A
replacement registered at the same path never inherits the old connection, and
the old connection's frames are refused with `404`. An explicit lease deadline
still rejects late calls in the kernel; it does not close the idle socket early.

Each route registration gets a unique id. An authenticated connection stores
the id it authenticated on and checks that id on its idle wait and on each frame
dispatch, so a same-path replacement cannot reach or inherit the old
connection. Dropping a registration removes only its own entry and wakes the
readers bound to it. Accepted connection join handles stay with the listener
until joined: close wakes and joins every connection thread and returns only
after they have exited, and finished threads are pruned as later connections
arrive.

Writes keep the 5-second write timeout. Opening readiness keeps the existing
open-deadline bound. The correction adds no reconnect, retry, replay, public
API, wire field, pin, or release metadata; one bearer, one authenticated
connection per lease, and the kernel's exact caller, per-call, and lease bounds
stay as they were.

## Highlights

This patch keeps the released package and route surface intact while fixing an
authenticated registered-tool courier that stayed quiet past the transport
timeout before SDK permission, binding its idle wait to the route registration
it authenticated on, and joining every accepted connection thread before close
returns.

## Provider-Free Evidence

The exact source patch from the immutable base is commit
`78f761c1032b7096bfa464af0adcde048f64d85b`, tree
`b739df554fd660c6cf729886d679bbd9ae2677f2`, patch SHA-256
`42e479a77efc7128167ad08129fb50750d6b9aa296eb35d4864a2629e8da85a0`.

The `validate:sdk-courier-idle` selector exercises the changed listener state
transitions with injected short boundaries, the real feature-gated courier with
idle gaps past the IO timeout, an explicit lease deadline expiring during idle,
cancellation during idle, watcher idle on the shared listener, and the prepared
Claude SDK facade with a real 45-second session age plus a 20-second pending
`canUseTool`. Only an SDK allow forwards the courier `tools/call`; a deny
forwards nothing, and a later turn still succeeds on the connected lease. The
`validate:sdk-courier-timeout` selector retains the released courier call-wait,
correlation, expiry, denial, and cleanup proof. Those selectors share one fresh
run-owned target from `scripts/run-with-owned-cargo-target.sh`. The
`validate:sdk-courier-ordinary` selector runs the same
`claude_agent_sdk_driver` binary through the hosted `ci-process` entrypoint with
no run-owned target, so it proves the task-owned fallback that ordinary `cargo
test`, plain `cargo nextest run`, hosted process, and MSRV entrypoints use: the
helper builds into its own marked target under the system temp root and removes
it when the last courier handle drops, never touching the worktree or a shared
target. No original provider executable,
credential, live provider request, or consumer mutation is involved.

This is offline producer proof only. There is no new Desktop live evidence for
this patch; a live gate remains separately authorized at exact identity.
