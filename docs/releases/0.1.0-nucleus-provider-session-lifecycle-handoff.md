# Nucleus Provider-Session Lifecycle Handoff

Status: bounded non-published `0.1.0` handoff
Consumer authority: Nucleus

This handoff keeps Nucleus thread lifecycle separate from optional provider
session management. It changes no Nucleus source and authorizes no consumer
policy.

## Ownership

Nucleus always owns:

- local thread archive, restore, and delete
- messages, attachments, tasks, memory, retention, and persistence
- confirmation, warnings, retry policy, and UI
- whether a local action also requests a provider action

Swallowtail owns one explicitly selected provider operation against one bound
inactive provider session. It never changes Nucleus thread state.

Local and provider results are independent. Neither result implies the other.

## Current Provider Actions

| Route | Archive | Restore | Delete | Exact delete truth |
| --- | --- | --- | --- | --- |
| Codex app-server | yes | yes | yes | `ProviderHardDeleted`; provider-defined descendants |
| Claude Agent ACP | no | no | yes | `ProviderDataDeleted`; provider-defined descendants |
| OpenCode HTTP/SSE | no | no | yes | `ProviderDataDeleted`; provider-defined descendants |
| Kimi Code local server | yes | yes | no | not available |

Codex archive guarantees only the selected target. Claude Agent and OpenCode
do not promise secure erasure. A future generic ACP delete defaults to
`HistoryRemoved` unless exact provider evidence qualifies stronger semantics.

Kimi Code ACP, Kimi headless, Gemini CLI ACP, and Gemini headless expose no
management binding. All other current routes either expose no manageable
persistent provider session or own only operation cleanup. Nucleus stays
local-only on those routes.

The exact 25-route posture remains in the
[provider route matrix](../guides/provider-route-matrix.md).

## Binding Rule

An `InteractiveSessionHandle` may expose a
`ProviderSessionManagementBinding`. Clone it before consuming the handle:

```rust
let management = session.management_binding().cloned();
let cleanup = session.close().await;
```

Dispatch no management action until close returns and Nucleus can honestly
assert that the provider session is inactive. A failed or uncertain close does
not justify that assertion.

A raw provider session id is never enough. Do not reconstruct authority from
logs, diagnostics, list results, local paths, or copied strings.

The current public binding has no stable persistence codec. Initial Nucleus
adoption must keep it in process. After restart or when no binding is present,
use local-only lifecycle. Durable binding export and import requires separate
Swallowtail contract and implementation work; opening or resuming a provider
session solely to manufacture management authority is not an implicit
fallback.

## Operation Sequence

1. Nucleus records the requested local action and optional provider action
   separately.
2. Nucleus obtains any required confirmation under its own policy.
3. Nucleus stops local work targeting the provider session.
4. Nucleus clones the management binding, closes the runtime handle, and waits
   for joined cleanup.
5. Nucleus selects the matching prepared adapter operation. It does not route
   by provider name or borrow another transport.
6. Nucleus decides whether a visible `UnverifiedNewer` attempt is allowed.
7. Swallowtail prepares one typed archive, restore, or delete operation.
8. Nucleus executes it once. There is no automatic retry or fallback.
9. Nucleus persists the local result and provider result independently.

Nucleus may order its own local persistence before or after the provider
action. It must retain partial success either way.

## Provider Result Projection

Persist at least these provider facts separately from the local thread result:

- requested action
- selected route and configured instance
- qualified or `UnverifiedNewer` posture
- `ProviderSessionEffectTruth`
- deletion strength, when deleting
- target-only or provider-defined-descendant scope
- safe request and rate evidence, when present
- stable bounded diagnostic, when present

The effect truth controls follow-up:

| Effect truth | Consumer meaning |
| --- | --- |
| `Applied` | provider confirmed the exact action |
| `AlreadyInTargetState` | provider confirmed archive or restore was already satisfied |
| `TargetAlreadyAbsent` | provider contract explicitly treats absence as success |
| `FailedBeforeEffect` | no provider effect occurred; a later explicit retry may be considered |
| `UnconfirmedAfterEffect` | request crossed the effect boundary; do not retry automatically |

Never promote `UnconfirmedAfterEffect` from a later list absence, connection
close, or local cleanup. Reconciliation needs a separate authorized operation
and provider evidence.

## Deterministic Consumer Scenarios

Nucleus adoption should cover:

1. Local-only archive, restore, and delete on every route with zero provider
   operation.
2. Codex local archive plus confirmed provider archive.
3. Codex delete preserving `ProviderHardDeleted` and descendant scope.
4. Claude Agent and OpenCode delete preserving `ProviderDataDeleted`, never
   secure-erasure wording.
5. Kimi local-server archive and restore; delete stays local-only.
6. Kimi ACP, Kimi headless, Gemini, and not-applicable routes staying
   local-only without a fabricated binding.
7. Provider `FailedBeforeEffect` with successful local action.
8. Provider `UnconfirmedAfterEffect` with successful local action and no
   automatic retry.
9. Provider success followed by local persistence failure, with provider truth
   retained for local retry or repair.
10. An `UnverifiedNewer` action refused before provider effects unless Nucleus
    explicitly allows it.
11. Driver-owned cleanup never satisfying a user-requested archive or delete.
12. Missing in-process binding after restart forcing local-only behavior.

These are behavioral cases, not UI-copy requirements.

## Rollback

Provider management is additive. Rollback disables optional provider actions
and retains universal Nucleus-local lifecycle. Do not delete stored local
outcomes or silently switch provider routes.

Dependency rollback follows the existing Nucleus `0.1.0` handoff. No package
publication, tag, release, or consumer edit is part of this document.
