# Swallowtail 0.1.0

Status: tagged 2026-08-06
Distribution: annotated Git tag only
Registry: not published
GitHub Release: not created

`v0.1.0` is Swallowtail's initial supported source identity. It coordinates 27
Rust library packages and 33 production routes behind explicit prepared
facades and provider-neutral runtime roles.

This document describes the immutable tagged source.

## Install

Select only the packages your application imports and use the same exact tag
for each:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.0" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.0" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.0" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.0" }
```

The tag must resolve on the
[canonical repository](https://github.com/inflatable-cookie/swallowtail)
before use. Do not mix the tag with another Swallowtail tag, a branch, a local
path, a registry placeholder, or an unreviewed revision.

## Highlights

- explicit configured provider-instance and model-route selection
- structured runs, interactive sessions, and realtime media where qualified
- model catalogues and exact model/reasoning selection where supported
- bounded events, usage, observable activity, task lists, and subagent topology
- typed questions, consumer tools, and permission exchange on capable routes
- exact session import, continuation, reconciliation, restoration, detachment,
  lifecycle management, and cleanup where provider evidence permits
- portable failure classification with exact safe diagnostics retained
- attached and host-owned local runtime routes without implicit process,
  endpoint, credential, model, or billing authority

These are route capabilities, not universal promises. Unsupported and
not-applicable cells remain explicit in the feature and activity matrices.

## Compatibility

The tag creates the first pre-1.0 Rust API and guaranteed-behavior baseline:

- compatible API or behavior changes advance the patch version
- breaking API or guaranteed-behavior changes advance the minor version
- provider and harness qualification remains a separate version axis

All 27 packages share version `0.1.0`. The reviewed semantic API contains
7,819 normalized entries. Every crate denies missing public documentation.

Verified compiler and target posture:

- Rust `1.90.0` for every package except Bedrock
- Rust `1.94.1` for `swallowtail-adapter-bedrock`
- Apple Silicon macOS

Other targets and newer compilers may work and remain unverified. Each route
guide names exact provider-interface ranges and unverified-newer behavior.

## Upgrade And Rollback

There is no earlier published Swallowtail release.

To move an existing path or revision integration to `v0.1.0`:

1. record the accepted source commit and retain the current `Cargo.lock`
2. change every direct Swallowtail dependency to the canonical Git URL and
   exact `v0.1.0` tag in one change
3. update and inspect `Cargo.lock`; confirm every Swallowtail package resolves
   from the same tagged source
4. run the application's deterministic integration and lifecycle checks
5. run live or authenticated smoke work only when separately authorized

To roll back, restore the previous manifests and lock file together. If a
temporary pre-release revision was explicitly approved, restoring that exact
`rev` is acceptable for rollback evidence but does not make it a release.
Never move or recreate `v0.1.0` to repair a failed release.

## Known Limits

- no crates.io packages, GitHub Release assets, binaries, sidecars, installers,
  or model artifacts are distributed
- the Claude Agent ACP npm sidecar remains an application-local prerequisite;
  the separate native `claude -p` route does not need it
- credentials, subscriptions, billing, endpoints, executables, attached
  services, and provider state remain host or provider owned
- Apple Silicon macOS is the only verified target for this release
- provider versions beyond exact qualified ranges are never silently
  guaranteed
- consumers own prompts, routing, retries, fallback, durable product state,
  transcript presentation, and UI policy
