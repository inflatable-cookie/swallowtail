# Swallowtail 0.2.0

Status: candidate 2026-08-06
Distribution: annotated Git tag only after exact CI acceptance
Registry: not published
GitHub Release: not created

`v0.2.0` adds one independently selectable package and one production route
over immutable `v0.1.0` and `v0.1.1`. Existing package APIs and route
identities remain compatible. The minor version is required because the
workspace now has one Rust `1.95.0` floor; raising an MSRV is breaking under
Contract 036. The source-only distribution boundary is unchanged.

## Install

After the candidate is tagged, use the canonical repository and exact tag for
every direct dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.2.0" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.2.0" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.2.0" }
swallowtail-adapter-muse = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.2.0" }
```

Do not use the candidate tag until canonical CI and exact tag identity are
recorded here. Never mix Swallowtail tags, branches, paths, registry
placeholders, or unreviewed revisions in one consumer graph.

## Highlights

- Muse Code joins the coordinated source release as package 28 and route 34.

## Compatibility

- Rust `1.95.0` is now the floor for every package. This is the release's
  intentional breaking change.
- Bedrock no longer carries a separate package-level Rust floor.
- Apple Silicon macOS remains the verified target.
- The original 27 package semantic APIs remain compatible with `v0.1.0`.
- Muse receives its first tagged semantic API baseline in this release.
- Provider and harness qualifications remain independent from package semver.

## Upgrade And Rollback

To upgrade, install Rust `1.95.0` or newer, change every direct Swallowtail
dependency to `v0.2.0` in one edit, update the consumer lock file, confirm every
Swallowtail package resolves from the same tag, and run deterministic
integration checks. Applications adopting Muse must also install and
authenticate the exact qualified harness outside Swallowtail.

To roll back, restore every direct dependency to `v0.1.1` and restore the
previous lock file in the same change. Muse has no earlier tagged package, so a
rollback must also remove or replace that route. Never move or recreate a tag.

## Known Limits

- no crates.io packages, GitHub Release assets, binaries, sidecars, installers,
  or model artifacts are distributed
- Muse has no provider catalogue, interactive continuation, callbacks,
  task-list snapshot, subagent control, usage evidence, retained-session
  recovery, or direct Meta Model API route
- the Claude Agent ACP npm sidecar remains an application-local prerequisite
- credentials, billing, endpoints, executables, attached services, and
  provider state remain host or provider owned
- consumers retain prompts, routing, retry, fallback, persistence, and UI
  policy

No authenticated provider call, consumer mutation, registry publication, or
GitHub Release is part of release preparation.
