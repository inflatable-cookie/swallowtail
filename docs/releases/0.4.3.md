# Swallowtail 0.4.3

Status: candidate; not tagged
Distribution: source-only candidate
Registry: not published
GitHub Release: not created

`0.4.3` is a coordinated pre-1.0 additive patch over tagged `v0.4.2`.
It carries Claude Agent SDK advisory and termination diagnostics, Claude
model/effort controls, and opt-in Grok ACP permission exchange.

## Install

After the operator authorizes and creates the tag, use the canonical repository
and the same exact `v0.4.3` tag for every direct dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.3" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.3" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.3" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.3" }
```

Do not mix tags, branches, paths, or registry placeholders in one consumer graph.
The candidate is not yet an installable release tag.

## Highlights

- Card105 validates pinned SDK `0.3.259` `rate_limit_event` envelopes with
  `allowed`, `allowed_warning`, or `rejected` status. During an active turn,
  each projects payload-free progress. Between turns, a valid advisory emits
  no turn event. The actual SDK result remains authoritative; `rejected`
  advisory alone does not manufacture a failure. Malformed envelopes, unknown
  statuses, and unknown message types fail closed. A deterministic two-turn
  sequence proves idle advisories do not prevent continuation.
- Card105 also preserves bounded termination codes, sanitized result-field
  observations, native-close evidence, and redacted stderr tails in consumer
  diagnostics. The stable code remains
  `swallowtail.claude-agent.sdk.sidecar_terminated`. Arbitrary provider error
  text does not cross the wire; a complete stderr drain is not claimed.
- Card082 adds bounded supported-model evidence and route-local model changes.
  Unsupported models reject before dispatch; confirmation-free SDK results
  return `model_change_unconfirmed` and retain the prior model. Optional
  open-time `low`, `medium`, `high`, `xhigh`, and `max` effort keeps
  init-confirmed versus requested-only evidence explicit. There is no
  mid-session effort setter.
- Card085 adds opt-in Grok Build ACP interactive permission exchange with
  bounded one-shot `allow_once` and `reject_once` choices, turn deadlines,
  and abandonment handling. Default reject-and-cancel behavior is unchanged.

## Compatibility

The semantic API comparison against tagged `v0.4.2` is additive only: Claude
model/effort evidence and Grok permission-exchange surfaces add public items.
Card105 changes no exported Rust API. No package or route is removed or renamed.
The candidate retains 40 packages, 49 production routes, Rust `1.95.0`, Apple
Silicon macOS as the verified target, and `publish = false` for every package.
Provider/native/runtime qualification axes are unchanged by this release.

Distinct `0.4.3` semantic API, production-route, and internal-dependency
inventories accompany this candidate. Existing `0.4.2` and older files are
preserved. The semantic generator uses `cargo-public-api 0.52.0` and
`nightly-2026-08-05`; this nightly does not change the stable Rust floor.

## Upgrade And Rollback

After tagging, change every direct Swallowtail dependency to `v0.4.3` together,
update the consumer lock, verify one exact tag throughout the dependency graph,
and run deterministic consumer checks. New controls remain opt-in.

To roll back, restore every direct dependency to `v0.4.2` and restore the prior
lock file in the same change. Do not mix coordinated workspace versions.
