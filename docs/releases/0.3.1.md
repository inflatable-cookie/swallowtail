# Swallowtail 0.3.1

Status: tagged 2026-08-08
Distribution: annotated Git tag only
Registry: not published
GitHub Release: not created

`v0.3.1` is a compatible source patch over the immutable `v0.3.0` baseline. It
keeps the same 28 packages, 34 production routes, Rust `1.95.0` floor, and
source-only distribution boundary while landing Contract 053 debug observation
and Contract 054 provider-session history pages.

## Install

After the candidate is tagged, use the canonical repository and exact tag for
every direct dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.1" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.1" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.1" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.1" }
```

Never mix Swallowtail tags, branches, paths, registry placeholders, or
unreviewed revisions in one consumer graph.

## Highlights

- Contract 053 opt-in debug observation: structured `DebugObservation` records,
  defaulted `DiagnosticObserver::observe_debug`, and fail-soft host emit helpers
  across production route families without changing safe diagnostics
- Contract 054 newest-first provider-session history pages with plan-bound
  cursors and `Exact` / `AtLeast` / `Unknown` totals, distinct from load and
  reconciliation
- history advertised on `codex.app-server`, `opencode.http`, and retained
  `alibaba.conversations`; Claude Agent ACP, Kimi ACP, and Kimi local-server
  remain unsupported until a control-free history wire exists (Research 115)

## Compatibility

No intentional breaking API changes. Consumers on `v0.3.0` can move every
direct Swallowtail dependency to `v0.3.1` in one edit.

Unchanged boundaries:

- 28 packages and 34 production routes
- Rust `1.95.0` floor and Apple Silicon macOS verified target
- exact provider and harness qualification remains separate from package
  semver
- source-only distribution with every crate retaining `publish = false`

## Upgrade And Rollback

To upgrade, change every direct Swallowtail dependency to `v0.3.1` in one
edit, update the consumer lock file, confirm every Swallowtail package
resolves from the same tag, and run the consumer's deterministic integration
checks.

To roll back, restore every direct dependency to `v0.3.0` and restore the
previous lock file in the same change. Never move or recreate either tag.

## Known Limits

- no crates.io packages, GitHub Release assets, binaries, sidecars, installers,
  or model artifacts are distributed
- the Claude Agent ACP npm sidecar remains an application-local prerequisite
- credentials, billing, endpoints, executables, attached services, and
  provider state remain host or provider owned
- consumers retain prompts, routing, retry, fallback, persistence, UI policy,
  and brand/icon assets
- authenticated provider and live-harness probes remain operator-gated and
  outside deterministic release preparation
