## Purpose

Establish a first-class native Claude Agent SDK route and independently widen
the existing Claude Agent ACP route as far as its qualified protocol permits.
Keep the route identities, evidence, packaging, lifecycle, and behavior
revisions distinct.

This milestone breaks the g05.021 release freeze by operator decision. It does
not authorize release preparation, tag work, a provider turn, token handling,
or production implementation before the two evidence gates close.

## Boundaries

- `claude-agent.sdk`, `claude-agent.acp`, Claude Code headless, and Claude Code
  response-only remain separate route identities.
- Swallowtail never holds or pools Claude subscription OAuth tokens.
- The native route uses a bounded sidecar boundary; it does not embed Node or
  TypeScript into the Rust process.
- Bash and terminal execution require explicit process-authority and consumer
  mediation evidence. Capability advertisement alone is insufficient.
- SDK-only features stay route-local until portable semantics are proved.
- No downloaded executable is run and no authenticated provider session is
  opened in cards 053-054.

## Acceptance

- official subscription authority and its provisional currentness boundary are
  frozen without token custody or inferred approval
- the native SDK route has an exact artifact/API/lifecycle/sidecar evidence
  packet and a bounded contract proposal
- the ACP route has a complete capability-to-support census and one or more
  independently deliverable tranches with exact withholding reasons
- every proposed shared abstraction is named by both source semantics or left
  for the orchestrator integration decision
- no route is flattened, no provider-specific feature is falsely portable,
  and no production claim changes during the evidence wave
- release readiness remains paused and must restart from a fresh exact-head
  audit after accepted Claude implementation

## Review Oracle

Invariant: each route publishes only behavior proved through its own exact
artifact, protocol, lifecycle, credential, and process-authority boundary.

Smallest counterexample: an SDK-only control attributed to ACP, an ACP
capability treated as effective without an acknowledgement or lifecycle proof,
one OAuth credential copied into Swallowtail state, or Bash admitted from tool
advertisement without a mediated execution boundary.

Required proof: exact artifact identities, public API/protocol inventories,
route-distinct ledgers, credential-flow negative evidence, lifecycle diagrams,
capability-to-contract mappings, and explicit withheld sets.

## Stop Conditions

Stop on changed Anthropic subscription guidance, an SDK license or packaging
barrier, required token custody, an unbounded sidecar/process boundary,
protocol evidence requiring a provider turn, shared vocabulary that cannot be
settled without an operator choice, or overlap between the two worker-owned
surfaces.
