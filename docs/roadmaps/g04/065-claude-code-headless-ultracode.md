## Problem

`claude-code.headless` exposes portable reasoning effort through
`default|low|medium|high|xhigh|max`, but not Claude Code's product-specific
Ultracode setting. Current official documentation describes Ultracode as
`--effort ultracode`: it sends `xhigh` and also enables dynamic workflow
orchestration. It is therefore not a seventh portable `ReasoningMode` and
cannot enter the existing effort set by name alone.

The exact qualified `2.1.241` help corpus does not list `ultracode` among the
advertised effort values. A binding is unsafe until exact package evidence
settles parser acceptance, model and entitlement support, dynamic-workflow
effects, tool and process topology, precedence, output grammar, and failure.

## Generation Runway Goal

Qualify the smallest exact adapter-local Ultracode selection on the existing
one-prompt `claude-code.headless` Plan-mode route. Preserve Ultracode's product
meaning without flattening it into reasoning effort, silently widening tools or
permissions, or adding process topology the route cannot observe and join.

## Named Scope

The lane is restricted to route `claude-code.headless`, driver
`swallowtail.claude-code.headless`, axis `claude-code.headless-stream-json`,
provider-supported local subscription access, and exact qualified package
points inside `2.1.220..=2.1.241`. Research 212 owns the first supported point
and exact model rows; no version or model is prequalified here.

The route already selects one exact model, owns one child process, fixes
`HarnessMode::Plan`, passes `Read,Glob,Grep`, disables session persistence,
suppresses MCP servers, and validates init/result/model/version truth. The only
candidate public shape is one adapter-local opt-in carried by prepared
evidence and the bound driver. It must not become a portable capability or raw
provider setting.

Ultracode and a separate portable reasoning selection are mutually exclusive.
If the product setting is admitted, its documented `xhigh` component remains
provider-private Ultracode behavior rather than a second public reasoning
request. Omission must retain the current argv byte-for-byte.

Dynamic workflows must not silently widen the route. If Ultracode can spawn
teammates or other children, select tools beyond the fixed set, persist state,
or require process lifecycle outside the existing owned child and task scope,
the lane stops unless exact evidence proves those effects are disabled or
fully contained by the selected command. Successful output does not prove that
Ultracode was effective.

cannot be flattened into portable reasoning or `ReasoningMode::xhigh`. Cards
