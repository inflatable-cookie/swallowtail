# Soundcheck Swallowtail 0.1.0 Handoff

Status: active non-published candidate handoff
Consumer authority: Soundcheck

Soundcheck already uses the Codex prepared integration in its sibling-source
development path. Candidate adoption changes only the dependency source; it
does not reintroduce manual preflight assembly.

## Dependency Change

Soundcheck currently consumes these packages from a sibling checkout:

- `swallowtail-core`
- `swallowtail-runtime`
- `swallowtail-host-local`
- `swallowtail-adapter-codex`

The release adoption shape replaces each workspace path dependency with exact
candidate version `=0.1.0`. Exact pins keep the first consumer rollout separate
from later compatible Swallowtail patches.

Before publication, isolated validation uses `[patch.crates-io]` entries
pointing to the four extracted candidate archives. After publication,
Soundcheck removes those temporary patches and resolves the same exact versions
from crates.io.

## Prepared Normal Path

Soundcheck selects and prepares Codex separately for each native role:

- app-server plus `prepare_catalogue` for model discovery
- structured exec plus `prepare_structured_exec` for bounded schema-driven
  analysis

Each profile retains exact executable-version assessment, access provenance,
the immutable plan, and matching runtime request. Catalogue and structured run
remain separate operations. Soundcheck retains prompts, schemas, model choice,
search and reasoning policy, authorization, workflows, persistence, and UI.
Swallowtail discovers no implicit provider, model, credential, executable,
endpoint, or sandbox.

## Minimum Toolchain And Target

- consumer minimum for these four packages: Rust `1.93`
- candidate current-stable validation: Rust `1.97.1`
- verified target: Apple Silicon macOS
- other targets and toolchains: unverified, not prohibited

## Relevant Provider Guarantees

Soundcheck uses the Codex structured exec route.

- maintained: `0.122.0..=0.146.0`
- deprecated: `0.80.0..=0.81.0`, `0.84.0..=0.121.0`
- exclusions: `0.108.0`, `0.109.0`
- stable versions above `0.146.0`: executable only as visible unverified-newer
  attempts, not guaranteed support
- gaps, exclusions, malformed versions, and unqualified prereleases: rejected

Soundcheck still owns prompts, schemas, search and reasoning policy,
authorization, workflows, persistence, and UI. The crate upgrade grants no
provider access or sandbox guarantee.

## Validation

Candidate proof uses a temporary copy of Soundcheck's current tracked and
untracked non-ignored source state. It:

1. replaces the four workspace path dependencies with exact `=0.1.0`
   requirements
2. patches crates.io to the extracted candidate packages
3. preserves the existing lockfile and sibling Soundcheck Library and Signal
   dependency sources; its locked `lucide-static` compile-time asset is
   supplied read-only from the original consumer worktree
4. runs `cargo test -p soundcheck-app swallowtail_codex:: --locked`

The original Soundcheck worktree and lockfile remain untouched.

Expected deterministic evidence is six passing Swallowtail Codex tests with
one installed/live probe ignored. The same package candidate also passes the
93-test packaged Codex lifecycle suite.

For consumer-owned adoption, Soundcheck should additionally run `effigy
health`, `effigy test`, and its normal desktop checks before merging.

## Rollback

There is no prior published Swallowtail version.

Rollback restores Soundcheck's pre-adoption manifest and lockfile, then
restores the four sibling path dependencies. For an exact source rollback,
extract the active or superseded source bundle named by its `candidate.env`
and point the paths at its four crate directories.

Do not silently fall back from a failed registry resolution or incompatible
Codex observation. Rollback is a consumer-owned manifest and lockfile change.
