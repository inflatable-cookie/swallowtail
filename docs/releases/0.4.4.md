`0.4.4` is a coordinated pre-1.0 additive patch over tagged `v0.4.3`. It
carries bounded Claude Agent SDK first-turn rejection evidence, the merged
provider-free registered-tool and selected-skill surfaces, the version-scoped

coordinated package version, route set, Rust floor, and provider qualification

## Install

Use the canonical repository and the same exact `v0.4.4` tag for every direct
dependency after the operator authorizes and creates that tag:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.4" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.4" }
```

Do not mix tags, branches, paths, or registry placeholders in one consumer
graph. Resolve every direct dependency to this exact immutable tag.

## Highlights

- Card119 adds bounded first-turn model-qualification evidence to the opt-in
  debug observer: requested and effective ids, catalogue size and digest,
  membership, source and phase, and declared, loaded, and native identity
  labels. The rejection predicate, code, order, and response shape remain
  unchanged. Provider-free alias-only, canonical-only, both-id, and neither-id
  fixtures cover the evidence and fail-soft observer path.
- Card120 verifies the loaded
  `@anthropic-ai/claude-agent-sdk` package manifest before `sdk.query` is
  constructed. Matching open evidence carries the loaded version; mismatch is
  typed `sdk_version_mismatch` with bounded declared/loaded identity, and an
  unreadable identity is typed `sdk_identity_unverifiable`.
- Card124 bounds identity lookup to the imported module's package boundary, so
  an unrelated ancestor manifest cannot masquerade as the SDK. Its sidecar and
  Rust paths share the C0/C1 control-character predicate for model evidence.
  Existing byte, catalogue, key, digest, observer, rejection, loaded-version,
  and terminal-retry bounds remain unchanged.
- Card121 makes every first-turn rejection terminal. A later retry fails with
  bounded `session_rejected_terminal` correlated to the original code, without
  replaying SDK input or provider work; explicit close remains available and
  genuine missing-init failures retain `init_missing`. Post-init prompt and
  turn-state rejections remain non-terminal where the fixtures prove the
  session is still usable.
- Merged Card083 adds opt-in provider-owned SDK resume and bounded session
  listing, while Card084 adds consumer-declared stdio MCP servers beside the
  Copy profile. `strictMcpConfig`, explicit child environment allowlists, and
  `canUseTool` mediation remain required; SSE/HTTP, in-process SDK servers,
  and managed MCP stay out. Card088 adds bounded vendor install guidance only
  to absent Claude Code, Codex CLI, and Grok Build discovery outcomes.
- Merged g05.035 implementation surfaces add the provider-neutral registered
  tool and operation-bridge vocabulary, selected skill/reference transport,
  and provider-free lifecycle checks. Card116's mediated stdio proxy accepts
  only the admitted MCP kind from a mixed snapshot; an all-`NativeClient`
  selection fails `unsupported_tool` before listener, lease, or dispatcher
  work. Card117 binds qualified Codex dynamic native tools to the same kernel.
  Card118's Grok evidence keeps consumer MCP unqualified. None of this is a
  live provider pass.
- Merged Cards 125-127 bind registered tools and selected skills to routes:
  Card125 binds the Contract 063 preparation into `claude-agent.sdk` open,
  Card126 carries one resolved selected-skill bundle through the pinned
  sidecar's explicit `systemPrompt` surface, and Card127 carries one through
  the Codex app-server `thread/start` parameters. Digest, bounds, reference,
  and redeclaration failures stay typed before provider work. Provider-free
  fixtures only.
- Merged Card142 ships the executable `admitted_claude_agent_sdk` worked
  example over admitted host-owned references; Card108 lets
  `claude-code.response-only` bind one host-approved `Read` working resource
  as the native child's project location. Nothing runs a live route.
- Merged Card118 gives `grok-build.acp` a callable registered-tool seam over
  the Swallowtail-owned mediated-stdio courier with turn-bound leases and
  serialized settlement; Card143 qualifies it version-scoped to Grok Build
  `1.0.4..=1.0.5` against the accepted capsules, with `version_not_admitted`
  refusal outside that segment. Provider-free fixtures plus frozen capsule
  identities; no fresh live pass.
- Merged Cards 144, 146, and 152 harden Claude SDK failure evidence
  provider-free: structured failed-open receipts with open stage and cleanup
  disposition, strict MCP-status projection admitting every declared optional
  `0.3.259` field, and end-to-end structured provider-failure facts with
  billing-specific `402` classification. No qualification or release
  consequence follows from these three alone.
- Merged Card153 qualifies `claude-agent.sdk` registered tools on the exact
  accepted Card 318 live tuple (Research 301): `Qualified` with

## Upgrade And Rollback

After the authorized `v0.4.4` tag exists, a separately authorized consumer
lane may change every direct Swallowtail dependency to `v0.4.4` together,
update the consumer lock, verify one exact tag throughout the dependency graph,
and run deterministic consumer checks. The new evidence and registered-tool
surfaces remain opt-in and route-specific.

To roll back, restore every direct dependency to `v0.4.3` and restore the
prior lock file in the same change. Do not mix coordinated workspace versions.
