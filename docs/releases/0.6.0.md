`0.6.0` is the coordinated pre-1.0 minor over tagged `v0.5.4` for the approved
currentness sweep. It carries the reviewed currentness qualifications already
on `main`, the approved TLS and emSign trust corrections, both released-line
courier corrections, the restored `v0.5.4` public lease API, and the additive
`opencode.acp` production route. Contract 036 forces the minor: several
consumer-visible guarantees change even though no public item is removed.

This note is candidate evidence. It is not a tag, publication, consumer repin,
live qualification, or release authorization.

## Install

Use the canonical repository and the same exact `v0.6.0` tag for every direct
dependency once that tag exists and is separately authorized:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.6.0" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.6.0" }
```

Do not mix tags, branches, paths, or registry placeholders in one consumer
graph. Until the tag exists, consumers stay on immutable `v0.5.4`.

## Compatibility

Contract 036 classifies these as breaking or consumer-visible before 1.0, so
the coordinated version advances the minor:

- **Opaque constructor narrowing.** Construction refuses more than 32 raw
  exclusion yields and Opaque version, exclusion, or behavior-revision text
  over 256 UTF-8 bytes. Released method signatures stay; accepted constructor
  inputs shrink.
- **Antigravity child projection.** A child that carries identity and no
  child status now projects `SubagentStatus::Unknown`; the earlier inferred
  `Completed` no longer applies.
- **Claude Agent SDK default pair.** Callers who previously received the
  released implicit `0.3.259`/`2.1.259` pair now receive `0.3.293`/`2.1.293`.
  The maintained enum has no `.259` variant, so `.259` remains available only
  on `v0.5.4`. Research 301's live registered-tool evidence stays bound to
  `.259`/`2.1.259` and does not transfer.
- **Command Code model-selection guarantee.** From `1.73.0`,
  `featureModels.planning` may precede `-m`, and the adapter applies that
  documented precedence. No public `model_request_start` activity is added.
- **Gemini ACP `0.63.0` restrictions.** `.gemini` writes and redirection ask
  the user, then reject and cancel; reads resolve real paths; protected
  `.env.*` files stay unreadable except example, sample, template, and dist
  names; tool output is capped at 64 KiB. HTTP MCP live honouring stays exact
  `0.61.0`.
- **Codex app-server `.aws` narrowing.** Inside `0.159.0..=0.161.0` an
  existing top-level `.aws` directory in the approved writable root is
  read-only. Earlier post-`0.155.1` segments keep their accepted revisions.

The semantic public API is additive against `v0.5.4`: 222 entries across nine
packages and no removals. `swallowtail-runtime` is identical to `v0.5.4`
because this candidate restores the seven lease methods released there. No
package is added, removed, or renamed; the 40-package set is unchanged.

Preserved pins and identity:

- Claude Agent SDK window `0.3.284..=0.3.295`, native
  `2.1.284..=2.1.295`, default `.293`/`2.1.293`
- Node `22.23.2` stays qualified inside `22.23.2..=22.23.3`
- SDK sidecar wire `swallowtail-claude-agent-sdk-jsonl-v1`, courier wire v1,
  MCP protocol `2025-11-25`
- Rust `1.95.0` floor, Apple Silicon macOS as the verified target, and
  `publish = false` for every package
- every older qualified provider segment, exclusion, and exact honouring
  point, including the exact HTTP MCP live points

No claim increases for Copilot CLI later than exact `1.0.80`, Kimi ACP later
than `0.38.0`, Kiro later than exact `2.21.4`, Grok catalogue later than exact
`1.0.30`, ZCode or Muse identity-only targets, Gemini headless later than

## Restored Public Lease API

`v0.5.4` released seven ordinary public registered-tool lease methods. This
`main` had hidden them behind `pub(crate)` or `#[doc(hidden)]`, which would be
a removal for `v0.5.4` consumers. The candidate restores each one with its
released signature and documentation; runtime deadlines, lifecycle, and
policy are unchanged.

- `PreparedRegisteredToolBinding::lease_deadline`
- `RegisteredToolBridgeLease::lease_deadline` and `next_call_deadline`
- `RegisteredToolOpenRequest::lease_deadline` and `with_lease_deadline`
- `RegisteredToolOperationKernel::next_call_deadline`
- `RegisteredToolPreparation::prepare_with_lease_deadline`

`check:lease-api-fixture` compiles an external consumer that names all seven
released signatures and calls them from an ordinary call site, then requires
each entry in the generated `0.6.0` semantic API dump. The existing
registered-tool lease lifecycle selectors keep their released proof; no new
original or live evidence is claimed.

## Test Entrypoint Correction

Task 177 introduced the strict run-owned courier target on `main` without the
matching ordinary-entrypoint fallback that `v0.5.4` shipped, so plain
`cargo test`, the MSRV floor test lane, and hosted `rust-floor-test` panicked
in every test that resolves the courier. This candidate restores the released
correction: the helper still accepts `CARGO_TARGET_DIR` only when it exactly
matches the validation runner's marked run directory, and otherwise builds into
one marked task-owned target directly under the system temp root that the last
courier handle removes. The resolved courier is a handle so that target
outlives the test using it. `validate:sdk-registered-lifetime` now runs under
the shared run-owned target. No timeout, runtime behavior, public API, pin, or
authority changed, and no test is skipped.

## Security

The candidate includes the reviewed `rustls` lock movement for
RUSTSEC-2026-0346, -0347, -0381, -0382 and -0383, and the exact emSign distrust
patches approved under Contract 023. Consumers whose endpoints chain through
`emSign ECC Root CA - G3` or the listed distrusted intermediates lose that
trust and see a generic certificate failure; no endpoint or live compatibility
is claimed for them. Unrelated roots, hostname and certificate verification,
and host authority are unchanged. No advisory is ignored, no emSign trust is
reintroduced, and released tags are not repaired by this candidate.
The lock also moves the transitive `ctutils` from `0.4.2` to `0.4.5` for
RUSTSEC-2026-0385, which affects non-constant-time mask generation and `u128`
comparisons on 32-bit targets. The path reaches `swallowtail-adapter-bedrock`
through `digest`, `hmac`, `aws-sigv4` and the pinned AWS SDK packages. The bump
is lock-only, stays inside the existing compatible requirement, keeps the Rust
`1.95.0` floor, and changes no manifest or provider, SDK, native, Node, or wire
pin.

## Upgrade And Rollback

Move every direct Swallowtail dependency to the single `v0.6.0` tag, update the
consumer lock, and verify one exact tag throughout the dependency graph.

- Callers relying on the implicit Claude Agent SDK `0.3.259`/`2.1.259` pair
  must select an explicit pair from the maintained window, or stay on
  `v0.5.4`. The `.259` live registered-tool evidence does not carry over.
- Callers relying on an inferred `Completed` Antigravity child status must
  handle `SubagentStatus::Unknown`.
- Callers that build Opaque claims with more than 32 exclusion yields or text
  over 256 UTF-8 bytes must reduce those values before upgrading.
- Gemini ACP `0.63.0` and Codex app-server `0.159.0..=0.161.0` consumers must
  expect the documented permission, read, and `.aws` write restrictions.
- Applications that need the optional lease deadline should use the restored
  public lease methods instead of relying on hidden internal plumbing.

To roll back, restore every direct dependency to `v0.5.4` and restore the prior
lock file in the same change. Older consumers keep the released SDK, native,
Node, sidecar wire, and route pins on that tag. Do not mix coordinated
workspace versions.
