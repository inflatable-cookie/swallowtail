# 041 Nucleus Native Application Pilot

Status: planned
Owner: Tom
Created: 2026-07-25
Milestone: `../014-consumer-scale-application-proof-and-hardening.md`

## Objective

Prove the current Swallowtail candidate through Nucleus's normal native
catalogue and Agent Chat path before sustained or writable work.

## Entry Gates

- card 040 complete
- Nucleus companion roadmap and consumer authority active
- unrelated Nucleus work checkpointed or non-overlapping
- isolated desktop state root, normal Agent Chat cancellation, proof deadline,
  and native Effigy proof selector available
- exact 15-attempt authenticated Codex ceiling approved
- live test data contains no private or durable user material

## Scope

1. Freeze the exact source, executable, model, access, topology, and fixture
   tuple defined by card 040.
2. Run 3 catalogue attempts across 3 native launches and 2 full restarts.
3. Run the 12 planned Agent Chat attempts: 6 ordinary successes, 3 read-only
   callback successes, 1 cancellation, 1 controlled deadline, and 1
   post-restart recovery success.
4. Prove 6 joined app-server lifecycles, no parallel turns, and no more than 3
   live children.
5. Capture the safe lifecycle, usage, rate, cleanup, persistence, and
   correlation evidence defined by card 040.
6. Use no more than 3 exact-scenario reruns and stop at 15 turns or 60 minutes.
7. File defects by Swallowtail or Nucleus ownership.

## Acceptance Criteria

- [ ] normal UI and server paths use the candidate
- [ ] exact executable and compatibility classification remain visible
- [ ] callbacks, cancellation, close, restart, and recovery retain truth
- [ ] 12 planned attempts pass within the 15-attempt and 60-minute ceilings
- [ ] no secret or raw provider payload enters stable evidence
- [ ] all Swallowtail defects have fixture-ready reproductions
- [ ] card 042 is ready only after pilot defects close

## Stop Conditions

- live authority or spend exceeds card 040
- the selected `gpt-5.4-mini` route is absent or changes access audience
- current consumer changes overlap the proof path
- cleanup, persistence, or provider truth becomes uncertain
- a defect requires changing consumer product policy
