`0.5.0` is a coordinated pre-1.0 minor release over tagged `v0.4.4`. It
carries the Pi RPC qualification through official npm `0.85.1`, the corrected
Claude native-mediation guarantee, and the Claude SDK registered-only session
profile. The minor bump, not a patch, is required by Contract 036: `v0.4.4`
documentation publicly said every admitted native tool under Claude SDK
`default` mode was offered through `canUseTool`, and the frozen Desktop
g02.049 capsules prove an in-workspace native `Read` may complete without
that callback. Correcting that guaranteed behavior is a guaranteed-behavior
shrink, which Contract 036 classifies as breaking before 1.0 — the same rule
that forced the `0.3.x` to `0.4.0` boundary. This note keeps the
source-only distribution explicit: the release line contains no crates.io
publication, GitHub Release object, binary, sidecar, installer, or model
artifact.

## Highlights

- g05.044 raises the qualified Pi RPC ceiling from `0.84.4` to official npm
  `0.85.1` on the `pi.rpc` strict-LF axis. The compatible extension keeps
  selected mapped commands and argv; published `0.85.0` is also qualified;
  `0.85.0` experimental server/client packaging, `PI_SERVER_*` help,
  persistent Claude thinking effort, in-memory session restore, and GPT-6
  Astra stay unmapped. Abort still waits for idle; compaction cancel is a
  bugfix of the already-mapped abort covering unmapped `compact`.
  Unpublished `0.83.1` and `0.84.5` stay incompatible, and unpublished
  `0.85.2` remains visible `UnverifiedNewer`. The `pi.sdk-sidecar` axis
  stays exact `0.84.2`. Research 302.
- g05.045 corrects the native-mediation guarantee. The three immutable
  Desktop g02.049 capsules (Research 303) show that on the qualified tuple —
  SDK `0.3.259`, native `2.1.259` darwin-arm64, Node `22.23.2`, sidecar
  `0.4.4`, `permissionMode` `default` — one native in-workspace `Read`
  proposal completed with zero `canUseTool` callbacks or decisions.
  Swallowtail still withholds `allowedTools` and answers every callback the
  SDK emits, but `canUseTool` is a permission request, not a universal
  pre-tool hook. `permission_exchange=Yes` stays scoped to the callbacks the
  SDK actually offers; registered MCP remains the Contract 063
  before-dispatch route; matrix Yes/No values, versions, and ranges are
  unchanged.
- g05.046 adds the registered-only Claude SDK session profile:
  `ClaudeAgentSdkRegisteredOnlyBinding` requires one non-empty qualified
  registered-tool selection, admits zero native SDK tools, and carries
  explicit `Read` or `ReadWrite` working-resource access. Open `tools[]`
  contains only selected carrier spellings, `allowedTools` stays unset, and
  `Read`, `Glob`, `Grep`, `Edit`, `Write`, `MultiEdit`, and `Bash` are
  structurally disallowed. Ordinary native constructors and additive
  `with_registered_tools` stay byte-compatible; empty native admission
  without the binding remains the typed early failure, and an extracted
  registered-only profile without its binding fails
  `profile.registered_only_unbound` at prepare before any lease, process, or
  provider contact.
- Documentation lifecycle and acceptance-audit changes since `v0.4.4` carry
  no extra runtime, provider, publication, or consumer authority.

## Compatibility

The semantic API comparison against tagged `v0.4.4` is additive only. The
candidate adds `ClaudeAgentSdkRegisteredOnlyBinding` with its structural
constructor and builders, the preparation
`with_registered_only` / `with_registered_only_binding` bindings, the driver
`with_registered_only` propagation, and the typed
`profile.registered_only_unbound` failure; no public item is removed or
incompatibly changed. No package or production route is added, removed, or
renamed. The candidate retains 40 packages, 49 production routes, Rust
`1.95.0`, Apple Silicon macOS as the verified target, and `publish = false`
for every package. Provider, native, and runtime qualification axes remain
separate and unchanged.

The release is still a minor, not a patch, because the corrected
native-mediation guarantee shrinks a documented `v0.4.4` guarantee:
consumers who relied on universal `canUseTool` mediation of every admitted
native tool under `default` mode no longer have that guarantee and must
mediate through registered MCP routes or accept the documented limitation.
Contract 036 classifies a guaranteed-behavior shrink as breaking before 1.0,
and breaking changes advance the minor version.

The candidate's `0.5.0` semantic API, production-route, and
internal-dependency inventories are generated from the current tree.
Existing `0.4.4` and older baselines remain immutable; the new files are
separate `0.5.0` baselines. The semantic generator uses
`cargo-public-api 0.52.0` and `nightly-2026-08-05`; this nightly does not
change the stable Rust floor.

## Upgrade And Rollback

After the authorized `v0.5.0` tag exists, a separately authorized consumer
lane may change every direct Swallowtail dependency to `v0.5.0` together,
update the consumer lock, verify one exact tag throughout the dependency
graph, and run deterministic consumer checks. Consumers relying on universal
`canUseTool` native-tool mediation must move the affected tools to registered
MCP routes or accept the corrected limitation; the registered-only session
profile is opt-in and route-specific.

To roll back, restore every direct dependency to `v0.4.4` and restore the
prior lock file in the same change. Do not mix coordinated workspace
versions.
