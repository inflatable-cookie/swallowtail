# Inactive SDK runtime permission packet

This is a source/security proposal, not applied workflow/helper source or an
activation request. The [revised diagnostic](claude-agent-sdk-preflight-diagnostic.md#consumed-revised-diagnostic-and-concrete-custody-gate)
owns observed cache bytes and the0777 refusal. The packet targets only that
existing22.23.4 fake-only leaf; it installs, copies and executes no runtime.
Its source changes cannot qualify Node22.23.4 for original SDK/native evidence.

The two unapplied patches add one helper and one manual contents:read Ubuntu
permission-only job. The existing registered diagnostic is read-only and cannot
be reused for mutation. Both application/registration and a later exact-source
activation choice remain separately reserved. No patch is applied by validation
outside fresh owned fixtures. JSON and detached record hold their exact hashes.

The command is the proposal JSON's futureCommand after source registration and
an exact owner grant; it is not ready for dispatch. bootstrapInputs:null is a
precise fail-closed prerequisite: obtain an independently bound complete loader,
library, interpreter and supervisor set for the actual fresh host. The candidate
report cannot supply its own bootstrap authority. Fresh directory descriptor
identities must establish every ancestor as root/job-owned and non-writable by
other groups/users. Leaf chmod alone cannot establish closure. Unexpected
ancestors/libraries require their own exact permission decision; no broad cache
rewrite or weaker custody rule is proposed.

The helper verifies source-bound candidate path/hash/size, ordinary ownership,
exact original0777 mode, a fresh non-symlink regular descriptor, ancestry and
all prerequisite bytes before writing durable intent. A private0700 receipt
root holds a0600 journal with fd identity, original/target modes and byte hash.
fsync of intent and parent directory precedes the sole fchmod0777→0755. Fresh
fd/path/byte checks precede the prepared receipt. The in-process primary always
rolls back; an independent cleanup reopens and verifies the exact original
object and complete prerequisites. It accepts only known0777/0755 modes,
restores0777 and proves identity/bytes/mode before recording cleanup:true.

Interruption after chmod but before receipt persistence leaves intent. Recovery
may restore only the same freshly verified object under the declared exclusive
trusted-host use. A changed object, bytes, mode, receipt binding or unsafe
ancestor/library refuses without touching an unbound leaf. Unknown cleanup
retains the journal, pending record, descriptors where the owner survives, and
failed observation; no journal is deleted. Independent cleanup's bounded log
summary preserves unknown/partial results if the primary was killed. This does
not claim filesystem custody survives a dead supervisor; recovery reacquires
and verifies inputs. Failure is not authority for another preparation attempt.

No candidate child is launched. A future in-process host composition may attach
actual owned Popen handles: stop/wait those children before restoring mode or
releasing custody. An orphan-child journal refuses independent rollback rather
than trusting caller settlement flags or killing reused PIDs. Runtime observation
or fake SDK/sidecar execution needs a separately bound source/host/runtime grant
and must retain the repaired live bootstrap capture; JSON receipt success is
not admission. The current permission-only job completes rollback without
executing a runtime, so it supplies permission/cleanup evidence only.

Bounds: one job/two minutes, primary20s+2s, independent cleanup5s+2s, internal10s,
receipt64KiB, retained receipt summary4KiB, no retry. Any timeout/unknown cleanup
fails. No sudo, new controller/cgroup/namespace/ptrace/canonical setup, provider
work or spend. Enabled parent controllers are metadata, not exclusive delegated
limits or enforcement. The combined22.23.2 pin, SDK0.3.317/native2.1.317 claim,
Node22.23.2..=22.23.3 axis, Q-009, ACP227 dependency and qualification hold remain.

Required ancestry is the exact candidate path's /opt, hostedtoolcache, node,
22.23.4, x64 and bin chain plus /; each identity/owner/mode remains to be
observed on the next fresh host. Required loader evidence includes its exact
ELF interpreter and resolved transitive DT_NEEDED/RPATH/RUNPATH inputs, pinned
/etc/ld.so.cache and absence of /etc/ld.so.preload, alongside complete Python
supervisor and any interpreter bindings. Those roles are currently null, not
implicitly approved paths or inferred file digests. Additional changes are
not authorized: any writable ancestor or library requires an enumerated later
owner ruling. The current packet's null manifest refuses before fchmod.
