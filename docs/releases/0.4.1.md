# Swallowtail 0.4.1

Status: released
Distribution: annotated Git tag `v0.4.1`
Registry: not published
GitHub Release: not created

`0.4.1` is a coordinated pre-1.0 patch release over `v0.4.0`. Research 286
found only additive or widening changes: the Claude Agent SDK read-write
session policy, Contract 061 candidate C, E, F, I, and J projections, the
provider-operation observation view, compound acknowledgement evidence, the
bounded-profile preflight widening, and the OpenCode HTTP qualification through
`1.18.28`. No breaking public API or guaranteed-behaviour change was found.
The package set remains 40, the release route inventory remains 49, the Rust
floor remains `1.95.0`, and Apple Silicon macOS remains the verified target.
Every crate remains `publish = false` and distribution remains source-only.

This note records the tagged source release. It does not authorize crates.io
publication, a GitHub Release, binaries, sidecars, installers, provider work,
or consumer-repository mutation.

## Install

Use the canonical repository and the same exact `v0.4.1` tag for every direct
dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.1" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.1" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.1" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.4.1" }
```

Never mix tags, branches, paths, registry placeholders, or unreviewed
revisions in one consumer graph. Before adopting the release, an external source consumer
must resolve every direct dependency from the exact candidate commit.

## Package Set

The 40-package set is unchanged from `v0.4.0`. It includes the foundations,
runtime and host support, protocols and transport, and the opt-in adapter
packages listed in the `v0.4.0` release note. OpenHands Agent Server remains a
package without a production route.

## Production Routes

The 49-route candidate inventory is unchanged from `v0.4.0`, including
`pi.sdk-sidecar` and `claude-agent.sdk`. Research 286 confirms that no route
was renamed or removed. The widening applies to existing routes:

- `claude-agent.sdk` keeps its exact qualified route and adds the explicit
  `default`, `plan`, and `acceptEdits` session profiles. Read-write profiles
  use the ambient-host, consumer-mediated admission posture and make no
  bounded-filesystem claim.
- Contract 061 candidate C adds additive projection contributions on
  Antigravity catalogue/headless, Bedrock catalogue/runtime, and Cursor ACP,
  catalogue, and headless.
- Candidate E adds additive Gemini and Grok projection contributions and
  projected-open seams while preserving existing opens.
- Candidate F adds additive Kimi ACP, headless, local-server, and Kimi
  Platform contributions, observation, and projected-open evidence while
  preserving exact reasoning/Plan and negotiated-model evidence.
- Candidate I adds additive DeepSeek continuation and DeepSeek Harness
  JSON-RPC/local-server contributions and completed catalogue/history
  observations; execution, paging, and cleanup are unchanged.
- Candidate J adds additive Llama.cpp attached/owned and Ollama attached
  contributions.
- `opencode.http` is qualified through `1.18.28` under Contract 029; the
  existing operations, lifecycle, and cleanup remain the same.

## Compatibility

Research 286 classifies the release as patch-compatible. Existing `v0.4.0`
public APIs, route identities, guaranteed behaviours, cleanup boundaries,
access posture, and source-distribution rules remain intact. New projection,
observation, and session-profile surfaces are opt-in or additive. The default
`claude-agent.sdk` profile remains the unchanged read-only `Read`/`Glob`/`Grep`
set under `default` mode.

No route was renamed or removed. No control authority, early provider work,
cleanup guarantee, provider-token flattening, or consumer-facing permission
was introduced. Qualified provider and harness versions remain a separate
Contract 029 axis from package semver.

## Upgrade And Rollback

To upgrade, change every direct Swallowtail dependency to `v0.4.1` in one
edit, update the consumer lock file, confirm every Swallowtail package resolves
from that same exact tag, and run the deterministic integration checks. Consumers
only receive the new projection, observation, or explicit SDK profile behavior
when they opt into those exact surfaces.

To roll back, restore every direct dependency to `v0.4.0` and restore the
previous lock file in the same change. Do not mix workspace versions, alias
routes, or treat prepared evidence as provider-operation observation. The
`claude-agent.sdk` default remains unchanged across the rollback boundary.

## Known Limits

- `claude-agent.sdk` write tools run under an explicit ambient-host posture
  with consumer-mediated per-call admission; `acceptEdits` auto-approves edits;
  no filesystem boundary is claimed
- Bash, mid-session model change, resume, and MCP on the SDK route remain later
  cards (081-084)
- the SDK route keeps its five exact qualified-only version pins until card 087
- Contract 061 coverage is 570 of 767 rows; candidates B, K, and L remain
- Kimi local server and Antigravity ceilings stay at `0.38.0` and `1.1.17`
  with named reopen conditions; Gemini remains deferred; the watcher stays
  exact `2.1.251`
- no crates.io packages, GitHub Release assets, binaries, sidecars,
  installers, or model artifacts are distributed
- authenticated provider and live-harness probes remain operator-gated and
  outside deterministic release preparation
