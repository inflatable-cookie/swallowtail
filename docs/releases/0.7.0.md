# Swallowtail 0.7.0

- Status — source-only release candidate
- Qualified preparation base — `e262042abc087a651e304ee483810932f281f448`
- Source commit and annotated tag object — pending review, hosted CI, and approval
- Hosted candidate CI run — pending
- Previous immutable release — `v0.6.0` at `8fe3bcbd90419debd075068f1dddfeac4626ba0f`
- Distribution — planned annotated Git tag `v0.7.0`
- Repository — https://github.com/inflatable-cookie/swallowtail

This coordinated pre-1.0 minor raises the Rust floor, consolidates shared
transports, and carries the lifecycle and resource-bound fixes already on
`main`. All 51 production routes carry over from `v0.6.0`. Distribution is
Git source only. The workspace has `publish = false` throughout.

## Install

Once the annotated `v0.7.0` tag exists, use it for every direct Swallowtail
dependency. Until then, use the immutable `v0.6.0` source tag.

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.7.0" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.7.0" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.7.0" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.7.0" }
```

## Compatibility

- The unified Rust floor rises from `1.95.0` to `1.97.1`. The candidate
  baseline pins Rust `1.100.0` for current-stable validation and keeps Apple
  Silicon macOS as the verified target.
- The unwired OpenHands Agent Server package is removed. Its start path
  failed closed, and it had no production route. Remove that dependency or
  keep the whole consumer graph on `v0.6.0`.
- `ClaudeAgentSdkPackageNativePair` becomes an opaque struct. The tagged enum
  had 12 variants. Replace variant references with `from_package_version`
  or `from_versions`. The maintained pairs and default remain available
  through `MAINTAINED` and `DEFAULT`.
- Claude Agent SDK and Grok registered-tool binding APIs accept a
  `RegisteredToolCourierService` implementation. Existing
  `LocalHostServices` arguments still work. The `host()` accessors now expose
  the runtime port. For guarded Claude Agent ACP capture, use the adapter's
  frozen recipe with the local host's `capture_frozen_guarded_recipe`.
- Synchronous `complete_sign_in` and `cancel_sign_in` return
  `SignInFinishFailure`, carrying the failure and the session. Keep the
  session and finish cleanup with the corresponding async operation when
  cleanup is pending.
- The Grok ACP client-MCP probe moves from `swallowtail-testkit` to
  `swallowtail-adapter-grok` behind `live-probes`. Update imports and enable
  that feature for probe callers. The provider-neutral testkit loses its
  ACP protocol dependency.
- Codex public protocol diagnostics redact wire excerpts and stderr. Use the
  opt-in diagnostic observer for those details. OpenCode session-history
  errors now use the operation's own cancellation and timeout codes and the
  runtime's provider-neutral incomplete-cleanup code.
- Pi and Claude Agent SDK wrappers derive their exact source identities from
  the coordinated version. Existing wire, provider-package and Node claims
  remain separate from that wrapper identity.

## Highlights

- Hill-Climb Rounds 1–2 hardened Claude, Codex, OpenCode, and Pi run,
  turn, and session cleanup. The fixes bound output, deadlines and queued
  activity, return leases when a start is refused, and surface cleanup
  failures. Shared follow-up work applies the same bounds to runtime,
  HTTP/SSE and ACP client paths.
- `codex.exec` and `codex.app-server` qualify through `0.171.0` on their
  separate claims. App-server lifecycle has a distinct milestone for
  `0.166.0..=0.171.0`. See [Research 487](../research/487-codex-exec-0-171-0-identity.md)
  and [Research 488](../research/488-codex-app-server-0-171-0-identity.md).
- `grok-build.catalogue` extends its `QualifiedOnly` window through `1.0.92`
  on `models-text-v2`. This is the model catalogue route. See
  [Research 491](../research/491-grok-build-catalogue-1-0-92-identity.md).

## Validation And Release Evidence

Milestone QA qualified the preparation base named above. Candidate
validation uses credential-free release gates and an isolated source
consumer. The release playbook assigns final hosted CI evidence to the
tag request. The qualifying run for that request must prove the final SHA
or an identical tree.

Source-only tag creation and push require operator approval of the exact
SHA. Consumer adoption and authenticated application smoke have their own
authority and evidence.

## Upgrade And Rollback

Use Rust `1.97.1` or newer, apply any API migrations above, and move every
direct dependency to the same `v0.7.0` tag once it exists. Update the consumer
lock and verify that it contains a single Swallowtail source identity. To
roll back, restore all direct pins to `v0.6.0` along with the previous lock
and any corresponding call-site changes.

## Deferred

Windows remains outside the verified target set. Pi RPC remains qualified
through `1.4.0`, OpenCode HTTP and ACP through `1.19.4`, and guarded Claude
Agent ACP through `0.106.0`. Later upstream artifacts have separate evidence
and qualification gates.
