# Swallowtail 0.1.1

Status: source-tag candidate
Distribution: annotated Git tag only
Registry: not published
GitHub Release: not created

`v0.1.1` is a compatible repair over the immutable `v0.1.0` baseline. It
preserves the same 27 packages, 33 production routes, compiler floors, and
source-only distribution boundary.

## Install

Use the canonical repository and exact tag for every direct dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.1" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.1" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.1" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.1.1" }
```

Do not mix Swallowtail tags, branches, paths, registry placeholders, or
unreviewed revisions in one consumer graph.

## Fixed

- Anthropic Managed Agents accepted cancellation now wakes the attachment pump
  and remains `Cancelled` when the operation deadline is concurrently ready.
- Kimi local-server detachment conformance now joins the fixture peer before
  reading peer-close evidence, removing a contention-only release-gate race
  without changing production detachment behavior.

## Highlights

The portable API and guaranteed capability surface are unchanged from
`v0.1.0`. Route support remains explicit through the provider route and
feature matrices; this patch does not flatten unsupported capabilities.

## Compatibility

- Rust `1.90.0` remains the general package floor.
- Rust `1.94.1` remains the `swallowtail-adapter-bedrock` floor.
- Apple Silicon macOS remains the verified target.
- The semantic public API baseline is unchanged from `v0.1.0`.
- Provider and harness qualifications remain independent from package semver.

## Upgrade And Rollback

To upgrade, change every direct Swallowtail dependency from `v0.1.0` to
`v0.1.1` in one edit, update the consumer lock file, confirm all Swallowtail
packages resolve from the same tag, and run deterministic integration checks.

To roll back, restore the previous manifests and lock file together. Never
move or recreate either source tag.

## Known Limits

- no crates.io packages, GitHub Release assets, binaries, sidecars, installers,
  or model artifacts are distributed
- the Claude Agent ACP npm sidecar remains an application-local prerequisite
- credentials, billing, endpoints, executables, attached services, and
  provider state remain host or provider owned
- consumers retain prompts, routing, retry, fallback, persistence, and UI
  policy

No authenticated provider call, consumer mutation, registry publication, or
GitHub Release is part of this release.
