# Codex Prepared Discovery Factory

Date: 2026-07-24

## Outcome

Card 008 is complete. Card 009 is ready.

The Codex adapter now prepares one explicit exec or app-server installation
from:

- stable configured-instance identity and revision
- one authoritative execution host
- one host-approved opaque executable target
- one opaque saved environment
- one explicit access profile
- observed or caller-asserted access status
- bounded probe lifecycle controls

The factory derives the installed-discovery request. Host and target are not
repeated by the caller. The exact probe target becomes the configured-instance
target, and the exact observation becomes its interface-version binding.

## Evidence

- exec and app-server retain separate descriptors, claims, facades, ownership,
  configuration posture, capabilities, and low-level driver entry points
- maintained `0.145.0`, deprecated `0.100.0`, excluded `0.108.0`, malformed,
  oversized, and unverified-newer `0.146.0` fixtures remain distinct
- exact compatibility behavior and access provenance remain inspectable
- host, target, and access drift fail before later provider effects
- spawn, bounded-output, exit, parse, classification, and cleanup stages remain
  machine-distinct and safely formatted
- local and remote-authoritative host identities use their own service sets
- debug formatting excludes raw executable paths and environment references
- the public prepared-discovery example compiles
- all 79 Codex tests pass
- Codex all-target check and warnings-denied clippy pass

## API Classification

This is additive pre-1.0 public API. It adds the prepared Codex factory and
more precise safe discovery diagnostics. Existing low-level discovery,
structured-run, catalogue, and interactive-session interfaces are unchanged.
The intentional public baseline refresh belongs to the unreleased superseded
`0.1.0` candidate.

## Continuation

Card 009 owns separate catalogue, read-only session, bounded-workspace session,
and structured-exec plans. It may derive immutable request agreement, but it
must not choose a model, workspace, network, search, reasoning, tools, schema,
attachments, or operation deadline.

Card 010 remains in bounds behind it. Consumer migrations, publication,
tagging, pushing, releases, workflows, and registry mutation remain out of
scope.
