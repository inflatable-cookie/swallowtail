`0.5.1` is a coordinated pre-1.0 additive patch over tagged `v0.5.0`. It
carries the OpenCode HTTP `1.18.30` compatible-extension ceiling and the Grok
Build `1.0.25` authenticated non-inference pre-session model catalogue,
including the additive `grok-build.catalogue` production route. Every path
under `crates/` in this candidate is byte-identical to the Desktop-qualified
g05.053 source `0209dd7f` that Desktop g02.089 Phase A proved green: the
release exists so that qualified implementation can be consumed through an
ordinary released pin instead of a raw revision. No runtime, provider,
dependency, or workflow behavior changes in this release.

## Highlights

- g05.051 raises the qualified OpenCode HTTP ceiling from `1.18.29` to
  official npm `opencode-ai` `1.18.30` on the `opencode.server` axis. The
  extension keeps `opencode.http-sse.surface-19`: selected HTTP/SSE route
  files and OpenAPI stay byte-identical, and the hop is proven from complete
  source-tree inventories because the published GitHub tags diverge. Unmapped
  Bedrock model-id resolution, unmapped GitLab reasoning-option shaping, and
  the unmapped GPT-6 Astra system prompt are the only shipped server source
  changes; provider SDK bumps and the explicit-service-tier patch stay
  provider-facing. Baseline `1.14.48`, claim id, historical gaps, and
  `AllowUnverified` stay; unpublished `1.18.31` remains visible
  `UnverifiedNewer`. Research 304, g05.051.
- g05.052 and g05.053 add the Grok Build pre-session model catalogue as a
  separately prepared `ModelCatalog` operation on exact installed `1.0.25`
  only. One bounded authenticated non-inference `--no-auto-update models`
  process with stdin closed unwritten reports ordered exact model ids and the
  source default under `HarnessConfigurationPosture::Ambient`; it may refresh
  authentication or bounded catalogue metadata but sends no prompt, opens no
  model session, dispatches no tool, invokes no inference, updates nothing,
  retries nothing, and retains no provider state beyond the bounded
  operation. The shipped exact-`1.0.25` bullet grammar owns membership,
  order, and default; the frozen embedded document supplements exact-ID
  matches only; malformed, duplicate, empty, over-limit, and
  ambiguous-default catalogues fail closed; `list_models_recorded` returns
  only redacted stdout/stderr byte counts and digests captured before
  parsing. The new `QualifiedOnly` claim
  `grok-build.catalogue.executable-1-0-25`
  (`grok-build.catalogue.models-text-v1`) admits no older or newer point; the
  ACP execution claim, `grok_build_model_for_version`, and released `v0.5.0`
  are unchanged. Research 305/306, g05.052, g05.053.

a source-only release line with no crates.io publication, GitHub Release

## Upgrade And Rollback

After the separately authorized `v0.5.1` tag exists, a consumer lane may
change every direct Swallowtail dependency to `v0.5.1` together, update the
consumer lock, and verify one exact tag throughout the dependency graph. The
Grok catalogue operation is opt-in and route-local; consumers who never call
`ModelCatalog` see no behavior change. OpenCode HTTP consumers gain the
qualified `1.18.30` ceiling without claim or surface changes.

To roll back, restore every direct dependency to `v0.5.0` and restore the
prior lock file in the same change. Do not mix coordinated workspace
versions.
