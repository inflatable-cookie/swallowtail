## Problem

Adapter mappings alone do not prove a usable provider-wide consumer surface.
Consumers need one exact activity inventory, package-level evidence, and a
handoff that keeps persistence and collapsed chat presentation downstream.

## Generation Runway Goal

Finish the observable-activity programme as a packaged multi-provider library
surface ready for application-scale Nucleus adoption.

## Goals

- [x] Publish one machine-readable solution activity matrix.
- [x] Prove every positive cell through a public prepared path.
- [x] Prove all local package archives and selected extracted-package paths.
- [x] Document a minimal consumer projection pattern.
- [ ] Produce bounded Nucleus and Soundcheck adoption handoffs without editing
      either consumer.
- [ ] Leave exact gaps and one next task.

## Non-Goals

- Nucleus or Soundcheck repository edits
- product database, message schema, or chat component implementation
- crates.io publication, tags, pushes, or releases
- live provider breadth testing
- claiming identical activity across routes
