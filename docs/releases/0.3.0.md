# Swallowtail 0.3.0

Status: candidate 2026-08-08
Distribution: annotated Git tag only after exact CI acceptance
Registry: not published
GitHub Release: not created

`v0.3.0` keeps the 28-package, 34-route source distribution from `v0.2.0`.
The minor version records one intentional breaking API correction: Codex and
Ollama version-binding helpers now reject invalid provider-observed versions
through `Option` instead of exposing an infallible signature.

## Install

After the candidate is tagged, use the canonical repository and exact tag for
every direct dependency:

```toml
[dependencies]
swallowtail-core = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.0" }
swallowtail-runtime = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.0" }
swallowtail-host-local = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.0" }
swallowtail-adapter-codex = { git = "https://github.com/inflatable-cookie/swallowtail", tag = "v0.3.0" }
```

Do not use the candidate tag until canonical CI and exact tag identity are
recorded here. Never mix Swallowtail tags, branches, paths, registry
placeholders, or unreviewed revisions in one consumer graph.

## Highlights

- installed-executable discovery, prepared-plan construction, run-loop event
  emission, and runtime plan-family validation now share provider-neutral
  scaffolding while adapter-specific claims and diagnostics remain explicit
- local process supervision bounds inherited-pipe reader joins and preserves
  force-stop race truth
- remote ACP HTTP and WebSocket work is deadline-bound and joined before
  cleanup completes
- runtime event and terminal senders close deterministically when their final
  producer is dropped
- provider-observed malformed input and unexpected tool-call shapes fail with
  safe exact diagnostics instead of panicking
- docs indexes, route inventory, MSRV selection, and version-parse rules are
  machine-checked

## Compatibility

Breaking source changes:

- `swallowtail_adapter_codex::codex_cli_binding(&str)` now returns
  `Option<InterfaceVersionBinding>`
- `swallowtail_adapter_ollama::ollama_runtime_binding(&str)` now returns
  `Option<InterfaceVersionBinding>`

Callers that used either binding directly must handle `None`, normally by
propagating a selection or version-parse failure. Do not restore infallible
`expect` handling for provider-observed text.

Unchanged boundaries:

- 28 packages and 34 production routes
- Rust `1.95.0` floor and Apple Silicon macOS verified target
- exact provider and harness qualification remains separate from package
  semver
- source-only distribution with every crate retaining `publish = false`

## Upgrade And Rollback

To upgrade, change every direct Swallowtail dependency to `v0.3.0` in one
edit, update the consumer lock file, handle the two optional binding results,
confirm every Swallowtail package resolves from the same tag, and run the
consumer's deterministic integration checks.

To roll back, restore every direct dependency to `v0.2.0` and restore the
previous lock file in the same change. Never move or recreate either tag.

## Known Limits

- no crates.io packages, GitHub Release assets, binaries, sidecars, installers,
  or model artifacts are distributed
- the Claude Agent ACP npm sidecar remains an application-local prerequisite
- credentials, billing, endpoints, executables, attached services, and
  provider state remain host or provider owned
- consumers retain prompts, routing, retry, fallback, persistence, and UI
  policy
- authenticated provider and live-harness probes remain operator-gated and
  outside deterministic release preparation
