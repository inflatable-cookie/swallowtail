## Goal

Determine the exact qualified Kimi Code ACP versions for which portable
`HarnessMode::Plan` can be selected and effectively confirmed before a new
session becomes ready, or promote an honest empty set.

## Work

1. Freeze current official plan-mode documentation only as a lead. Fetch exact
   public npm/source identities for qualified Kimi Code points and locate the
   first complete ACP mode-option milestone plus its preceding boundary.
2. Digest the decisive mode registry, config-option builder, session/server
   dispatcher, SDK plan/permission application, status/readback path, and exact
   tests at every relevant milestone.
3. Prove the exact snapshot option id, category, type, row values, ordering,
   initial/current value, duplicate/malformed behavior, and foreign-row
   disposition.
4. Prove the exact request path and mapping for `plan`, including
   `setPlanMode(true)`, manual permission, rejection/fallback behavior, emitted
   updates, and response `currentValue` truth.
5. Keep requested, planned, dispatched, accepted, effective, and observed
   states distinct. Source labels or a successful request alone are not
   effective confirmation.
6. Prove omission plus composition with every admitted reasoning value. Settle
   request order, independent confirmations, partial failure, disconnect,
   deadline, cancellation, and joined cleanup before the first prompt.
7. Classify new, load, resume, import, and recovery lifecycles. No attachment
   mutation may be inferred from provider persistence.
8. Classify exact compatibility behavior, `UnverifiedNewer`, permission,
   isolation, access, model, resource, retention, and diagnostic boundaries.
9. Promote Research 208 with one exact deliver-now table or an explicit empty
   set. Update the milestone/card status and reserved closeout honestly.

## Acceptance Criteria

- [x] exact first complete plan-mode milestone and preceding boundary are frozen
- [x] exact snapshot, request, SDK application, permission, response, and update
      behavior are explicit
- [x] every candidate version/value row has requested through effective truth
- [x] `default|auto|yolo`, unknown rows, malformed shapes, drift, rejection,
      and fallback have explicit dispositions
- [x] reasoning composition and every failure-before-readiness path are bounded
- [x] load/resume/import/recovery mutation authority is explicitly absent
- [x] ambient isolation and manual permission remain independent claims
- [x] Research 208 is promoted with a non-empty exact table or honest empty set
- [x] no production code, public API, shared contract/runtime, currentness,
      release, or generation state changes
- [x] `effigy qa:northstar`, relevant research/roadmap/log index gates, and
      `git diff --check` pass

## Stop Conditions

- exact source/artifact identity or first complete behavior cannot be frozen
- `plan` can fall back, substitute permissions, or lacks effective confirmation
- safe qualification needs a provider prompt, credential/account state,
  arbitrary config exposure, public `auto|yolo`, or shared contract change

## Out Of Scope

- production binding, another Kimi route/feature, live provider work,
  currentness, release, merge, generation rollover, or g04 closure
